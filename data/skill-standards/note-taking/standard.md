# Note Taking Standard v1

> keywords: 记下来, 保存, 笔记, 记录, 写入, 追加, Obsidian, 备忘录, 存档, 存一下, 帮我记, 记住这个, save, note, write, append
> Bobo 在做任何笔记写入/记录任务时必须遵守本文档。本文件是硬约束，不是建议。
>
> **工作流（必须遵守，不可跳过）**：
> 1. 先搜 → search_obsidian 检查是否已有相关笔记（避免碎片化）
> 2. 再判 → 有同主题笔记 → append；无 → 新建
> 3. 选位置 → 根据内容主题匹配最佳文件夹（不是全部丢到根目录）
> 4. 写内容 → 带 frontmatter（tags + 日期），结构清晰
> 5. 后验证 → read_obsidian 或 read_local_file 确认写入正确
> 禁止跳过搜索直接写入。禁止不验证就声称"已保存"。
>
> **设计哲学**：每篇笔记都应该是未来可找到的。搜索优先于创建，追加优先于新建。文件夹不是装饰——它决定三个月后你还能不能找到这篇笔记。

## 约束

### 绝对禁止（违反任一条 = 不合格）

- ❌ 不搜索就写入——每次写入前必须先用 `search_obsidian` 检查是否有同主题笔记
- ❌ 同主题内容创建多篇碎片笔记——已有相关笔记时必须 `append_obsidian` 追加，不得新建
- ❌ 笔记丢到 vault 根目录——必须根据内容主题选择目标文件夹
- ❌ 空 frontmatter——每篇笔记必须带 `tags:` 和 `date:` 元数据
- ❌ 写入后不验证——`write_obsidian` 或 `append_obsidian` 之后必须用 `read_obsidian` 确认内容正确写入
- ❌ 不标注信息来源——如果内容来自 web_search 或外部资料，必须标注来源 URL
- ❌ 覆盖或删除已有内容而不确认——修改已有笔记前必须先展示差异，获得用户同意

### 必须遵守

- 每次写入后立即用 `read_obsidian` 读回，确认文件存在且内容正确
- frontmatter 格式：
  ```
  ---
  tags: [标签1, 标签2]
  date: YYYY-MM-DD
  ---
  ```
- 文件名用中文或英文均可，但必须能反映内容主题。不要用 `未命名`、`新笔记`、`笔记1` 等无意义名称

## 工作流状态机

### Step 1: 搜索（SEARCH）

**目标**：避免创建重复或碎片化的笔记。

**步骤**：
1. 从内容中提取 2-3 个核心关键词
2. 调用 `search_obsidian` 搜索这些关键词
3. 检查返回结果：
   - 标题相似度 > 60% → **Step 2a: 追加**
   - 内容主题相关但标题不同 → **Step 2b: 新建（链接到已有笔记）**
   - 完全无相关结果 → **Step 2c: 新建**

**决策规则**：宁可把相关内容追加到一篇长笔记，也不要创建 10 篇小笔记。

### Step 2a: 追加（APPEND）

**目标**：在已有笔记后补充新内容，保持主题集中。

**步骤**：
1. 调用 `read_obsidian` 读取已有笔记内容，了解当前结构和截止点
2. 判断新内容属于笔记的哪个章节——如果已有对应章节，追加在该章节末尾；如果没有，新建章节
3. 调用 `append_obsidian` 追加，格式：
   ```
   ---
   ## YYYY-MM-DD 更新
   [新内容]
   ```
4. 调用 `read_obsidian` 验证追加成功

### Step 2b: 新建（CREATE）

**目标**：创建一篇结构清晰、未来可检索的新笔记。

**步骤**：
1. 确定目标文件夹：
   - 列出 vault 的顶级文件夹（`list_directory`）
   - 按内容主题匹配最相关的文件夹：
     - 项目相关 → `项目名/`
     - 学习笔记 → `学习/` 或 `技术/`
     - 会议记录 → `会议/`
     - 个人思考 → `日记/` 或 `想法/`
     - 无匹配文件夹 → 在合适的父目录下创建子文件夹
2. 确定文件名：`[主题关键词] - [简短描述].md`（如 `Bobo开发 - Skill系统重构方案.md`）
3. 构造完整内容：
   ```
   ---
   tags: [tag1, tag2]
   date: YYYY-MM-DD
   ---
   
   # 标题
   
   ## 背景
   ...
   
   ## 内容
   ...
   
   ## 结论 / 待办
   ...
   ```
4. 调用 `write_obsidian` 一次写入完整内容（不要分多次 `append_obsidian`）
5. 调用 `read_obsidian` 验证写入正确

### Step 2c: 链接（LINK）

如果搜索结果中有主题相关但标题不同的笔记，在新笔记中使用 `[[笔记名]]` 链接到它们，建立知识图谱。

### Step 3: 验证（VERIFY）

**目标**：确认内容已正确持久化。

**步骤**：
1. 调用 `read_obsidian` 或 `read_local_file` 读回文件
2. 检查：文件存在 ✓、内容完整 ✓、frontmatter 正确 ✓、格式正常 ✓
3. 向用户报告：文件路径 + 内容概要（一句话）

## 文件夹匹配规则

根据内容类型自动选择目标文件夹：

| 内容类型 | 匹配关键词 | 目标文件夹（示例） |
|---------|-----------|-----------------|
| 项目开发 | bug, 修复, feature, 代码, 架构 | `项目名/` 或 `开发/` |
| 学习笔记 | 学习, 教程, 笔记, 概念 | `学习/` 或 `技术/` |
| 会议记录 | 会议, 讨论, 决定 | `会议/` |
| 个人思考 | 想法, 反思, 计划, 目标 | `日记/` 或 `想法/` |
| 读书笔记 | 书, 阅读, 读后感 | `阅读/` |
| 工作汇报 | 汇报, 总结, 进度 | `工作/` |

**如果没有匹配的文件夹**：在 vault 根目录或合适的父目录下创建新文件夹，文件夹名用中文。
