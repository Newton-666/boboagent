# TICKET-AUTO-G3：prompt.submit 中断等待窗口修复

> 立案：2026-08-10 · owner 实弹发现：ESC 中断后立刻发新消息，报"无法取消上一个请求，请稍后重试"
> 根因（已代码核实）：E-1 中断保进度让引擎退出从"立即 return"变为"先落盘再退出"（1-2s），
>   而 prompts.py:104-111 的 cancel 后只等 0.3s 就报错——等待窗口配不上新的退出时长。
> 分支：feat/ticket-auto-g3（自最新 main 切出）
> 纪律：branch 施工、五查汇报、未终审不 merge 不 push

---

## 一、施工内容（1 项，刻意小）

`handle_prompt_submit`（bobo_tui_gateway/handlers/prompts.py:104-111 及 :396 附近同逻辑处）：

- `cancel(sid)` 后的"sleep(0.3) + 单次检查"改为**轮询等待最长 3 秒**：每 100ms 检查 `is_running(sid)`，引擎消失立即放行；
- 超过 3 秒仍在跑 → 保留原报错（"无法取消上一个请求，请稍后重试"）——兜底行为不变；
- 引擎本来没在跑的路径零改动（不进等待逻辑）。

## 二、副作用约束（owner 点名要求）

- 最大新增等待 = 3 秒，且仅在"引擎还在退出中"时发生；
- 不得改成无限等待；不得吞掉报错兜底；
- 正常模式 / auto 模式共用此路径，两模式行为一致变化（可接受：只少报错，不改语义）。

## 三、验收（终审口径）

1. 模拟"引擎退出耗时 1.5s"（测试里桩住 is_running）→ submit 成功，无报错；
2. 模拟"引擎永不退出"→ 3 秒后报原错误（兜底钉死）；
3. 引擎未运行 → 不进入等待，立即受理（零回归路径）；
4. :396 处同逻辑一并修复（/duo 透传路径）；
5. 全量 pytest 零回归（基线 1702 passed / 2 skipped）；真实库 md5 闸门照旧。

## 四、边界（明确不做）

- 不动 E-1 中断保进度逻辑（退出慢是特性不是 bug）；
- 不动前端重试逻辑；
- 不改报错文案。
