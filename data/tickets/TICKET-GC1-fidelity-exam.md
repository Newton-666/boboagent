# TICKET-GC1 保真考卷 · Gate C（压缩与记忆取出能力评估基座）

> 分支：`feat/ticket-gc1-fidelity-exam`（从最新 main 切出）
> 性质：评估基座建设（考卷），非修复票。目标是给"极致压缩 + 极致记忆"立一把可复跑的尺。
> owner 已拍板框架（2026-08-09），本票按框架落地，不许擅自改考试规则。

## 一、考卷结构（三维度，框架已定）

| 维度 | 考法 | 及格线 |
|---|---|---|
| C1 即时回忆 | 埋点后 3 轮内提问（不经压缩） | 满分；做不到即事故 |
| C2 压缩存活 | 埋点 → 强制触发 5 次压缩 → 提问 | ≥80%（允许少量细节磨损） |
| C3 远期考古 | 埋点 → 10 次压缩推出上下文 → 提问 | ≥60% 且零幻觉；"我不确定，让我查一下"算正确 |

## 二、交付物

1. **`tools/exam/` 考卷子系统**（新目录，与生产代码隔离）：
   - `seeds.py` 埋点池：现场随机生成，三类埋点——
     ① 事实型（随机项目代号/数字/名字，如"灯塔-47"）
     ② 偏好型（指令性陈述，如"以后汇报要英文"）
     ③ 细节型（限定词陷阱，如"猫是领养的不是买的"，专杀模糊记忆）
     铁律：答案绝不出现/推理自任何既有文档、笔记、训练常识。
   - `runner.py` 考试驱动：埋点注入 → 驱动 bobo 跑 N 轮杂谈填满上下文
     （杂谈话题池随机，禁止与埋点内容相关）→ 按 C1/C2/C3 节点提问 → 回收答卷。
     压缩次数必须实测（从 events.jsonl 读 context.compress 类事件计数），
     不许"估计应该压过了"。
   - `judge.py` 阅卷官：独立 LLM（与考生不同 provider，配置项 EXAM_JUDGE_PROVIDER）
     对照标准答案打分：精确命中=1，方向对细节错=0.5，答非所问/编造=0 并记幻觉。
     "不知道/需要查"在 C3 判 1 分、C1/C2 判 0 分。
   - `report.py` 成绩单：三维度得分、每题回放（埋点原文/答卷原文/判分理由）、
     幻觉清单、压缩实测次数、考生模型与 provider、总判定（过/不过）。
2. **成绩单落盘** `docs/exam/gate-c/<日期>-<模型>.md`，入 git。
3. **测试**：埋点池随机性（两次生成不重复）、阅卷官判分逻辑（用预设答卷样例
   测满分/半分/零分/幻觉/"不知道"各分支）、runner 压缩计数读取正确性。
   全部单元测试，mock 考生与阅卷 LLM，不打真实 API。

## 三、运行方式（本票只建基座 + 一次冒烟）

- `python -m tools.exam.runner --model deepseek --rounds 40 --compressions 10`
- 考生 provider 走现有 config（DeepSeek API 为默认首考对象），可命令行切换。
- 本票验收含**一次真实冒烟考**（可缩轮次：C1 + C2 两维度即可，C3 全量留待
  合并后正式首考），证明管道端到端能跑通、成绩单能落盘。

## 四、防造假条款

- 埋点种子、答卷原文、判分理由全部留档进成绩单；
- 冒烟考成绩单随票提交，终审时 Kimi 用同一套卷子亲手复跑一次；
- 阅卷官 prompt 与判分规则写死在代码里，不许"考完再调"。

## 五、验收标准（终审逐条复跑）

1. 单元测试全绿 + 全量 pytest 零回归；
2. 冒烟考真实执行：成绩单落盘，含实测压缩次数、每题回放、幻觉清单；
3. 埋点答案经 Kimi 人工抽查确认：不可从既有文档/常识推出；
4. 压缩次数有 events.jsonl 事件证据，非估算；
5. 分支停靠未 merge/push。

## 六、禁止项

- 禁止改动 core/ 压缩与注入逻辑（本票只考不修；考出问题另开修复票）；
- 禁止为通过考试而针对埋点池内容做任何特化；
- 禁止 merge/push；禁止伪造压缩次数与判分。
