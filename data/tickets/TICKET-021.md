# 票 TICKET-021：失忆自查协议——忘了就去翻知识库

## 病灶（已实锤）

知识库（living notes）指针每轮都在重新注入（injector.build_messages 每轮调用，
这块没问题），但 bobo 仍不翻笔记，两个原因：

1. **指针文案是建议口吻**："深入讨论请先用 read_local_file 读全文再答"——
   模型可读可不读，工具调用压力下必然不读。
2. **身份段没有"忘了怎么办"的协议**：模型意识到自己丢失上下文时，
   没有任何指令告诉它知识库的存在和翻阅路径。它只能硬编。

用户实测原话："他明明可以翻我们的知识库系统，但他没有往这边做，
然后他后面就忘记之前做过什么事情。"

## 目标

### A. 失忆自查协议（injector 身份段追加，硬性指令口吻）

在系统提示身份段追加（预算内，≤250 字符）：

```
【上下文自查协议】当你无法确定本会话之前做过什么、或用户引用你没有印象的
前文时：禁止猜测。先 read_local_file 读 data/library/index.md 找相关笔记，
再读笔记全文恢复上下文。笔记是你在过去会话中亲手写的工作记录，可信。
```

（library 路径以实际为准，若 _LIBRARY_DIR 已有常量则复用）

### B. 指针文案升级（injector.py:416 附近）

建议口吻 → 指令口吻：
`📚 关联笔记：{domain}/{topic}.md（v{N} · {last_touched}）— 回答相关话题前必须先 read_local_file 读全文，凭记忆回答视为违规`

### C. 压缩后指引（依赖 TICKET-020 的工作锚点，若 020 未合并则本项独立实现）

压缩发生后，下一轮系统提示的笔记指针段置顶一行：
`⚠️ 历史已压缩。若对早前工作有疑问，先翻阅上方关联笔记再作答。`

无关联笔记时此行省略。

## 边界（不碰）

- 笔记生成逻辑（living_notes.py）不动
- 指针关联判定（sid 命中/主题词命中）不动
- 各段预算比例不动（身份段全量段内消化，笔记段 6% 不变，文案变长自行精简）

## 验收

1. 协议注入：构造含 library 的环境 → 系统提示含【上下文自查协议】段；
   无 library → 协议段仍在（协议不依赖 library 存在，它是行为指令）
2. 指针文案：关联笔记命中时含"必须先 read_local_file"字样
3. 压缩后指引：触发压缩后下一轮 build_messages 输出含"历史已压缩"指引；
   无关联笔记时该行缺席
4. prompt.budget 事件字符数与实测一致（LN-4/LN-5 监控不回归）
5. 全量 pytest 零回归（基线 1429 passed / 2 skipped）
6. 改 core/ → 五查第 6 项填"是，需重启"
