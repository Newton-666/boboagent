## 2. 统一窗口模式（通信设计）

**原则**：所有部门连接统一为一种——"走廊递简报+申请 → 部门答结果 → 走廊决定"。禁止再新增其他接法。

| 部门 | 走廊递给它 | 它还给走廊 |
|---|---|---|
| 安全部 | "这命令危险吗"（命令文本） | 放行/拦截 + 理由 |
| 工具执行部 | "执行这批工具"（调用+上下文） | 每工具结果 + 状态 |
| 上下文部 | "组装这轮背景"（历史/记忆/技能） | 组装好的上下文 |
| 三间小屋 | （墙内窗口同款） | 放行/拦截/观察 |
| 出口组装部 | "拼成终稿"（草稿/台账/交接） | 拼好的终稿 |

模式复刻自 core/steps/ 的白名单窗口（StepContext：简报只读 + 办事窗口 + 回话），推广到全 harness。

## 3. 收益假设（HYPOTHESIS——可验证，非空承诺）

> 以下为**预期**，每项配测量方法，落地后对账；对不上的如实报告。

### 内部（最确定的收益）
| 假设 | 测量 |
|---|---|
| 连接方式 4 种 → 1 种，可重排性提升（重组免费） | 部门替换/重排的实验成本（改动行数） |
| 每个部门可独立测试 → 回归风险下降 | 每部门独立测试套件 + 全量保持绿 |
| 骨干可见 → 排查/审计容易 | 故障定位时间（主观，按经验记录） |
| 补偿型约束可单独拆除 → 模型换代清理容易 | 每部门可独立开关（A/B 验证） |

### 表象
| 假设 | 预期 | 测量 |
|---|---|---|
| engine 体积 | **缩小**（走廊变瘦，逻辑外移） | engine.py 行数（当前 ~1700） |
| token / 调用数 | **短期持平**（行为保持解耦不改调用结构）；**中期下降**（补偿型约束可拆后） | scripts/engine_eval.py（B26 基线） |
| 速度 | 持平（窗口调用微秒级，相对 LLM 秒级可忽略） | engine_eval 耗时 |
| 准确度 | **不变**（行为保持） | 行为基线 diff=0 + 全量 |
| 故障定位 | 更快（部门独立验证） | 主观记录 |

### 关键诚实点
- 解耦本身**不省 token**（行为保持）——token 下降是"解耦后能安全拆补偿约束"的**中期**收益，不是本设计的即时收益；
- 本设计的第一收益是**内部**（可重排/可测/可拆），表象收益滞后。

## 3b. 宏观设计原则：默认休眠，路由激活（default dormant, router-activated）

> owner 类比（2026-08-23）：现在的 harness = 全量模型（每轮全量激活所有部分）；
> 目标 = MoE（混合专家）——一个"路由器"按任务×用户激活相关专家，其余休眠。
> 省资源不损性能的前提：**不是每次都需要 skill/工具/记忆**。

- **原则**：harness 每个组分默认不进入上下文，由路由器按"任务 × 用户"决定激活谁。固定底座（身份/状态）除外。
- **路由器 = 适配层（灵魂）的家**：学习 = 学会路由（工具选择/注入选择/记忆排序全是路由决策），不是学会生成。
- **诚实的代价**：路由错了性能就掉——路由器质量决定一切（技术层信号设计护栏的落点）。
- **同时解决三件事**：token 成本（休眠省）、注意力质量（不稀释）、灵魂落点（路由器 = 适配层）。
- **审视任何组分的提问方式**：它的路由器在哪、路由对不对——而不是"怎么被全量塞进去"。

## 3c. 能力层设计：挂包协议 + 描述即路由判据

> owner 2026-08-23 定：**LLM 判断挂包靠的是 description——清晰的人类可读描述，比关键词/信号准得多**。
> 工具/技能/未来 MCP 统一为"挂包"（可插拔包），路由判据 = 描述语义，不是元数据匹配、不是信号。

- **每个挂包的铭牌 = 一条高质量描述**（服务什么任务 / 什么时候用 / 什么时候不用）；
- **路由 = 两段**：① 廉价预筛（关键词/类型，只为省钱缩小候选——不是路由本身）；② 语义判断（LLM 或向量：读描述 × 当前任务意图 → 决定激活谁）；
- **描述质量 = 路由准确率的杠杆**：写清楚一条描述，比调任何信号有效；描述是一等公民（新挂包必须带合格描述，有验收标准——技术层"挂包规范"）；
- **路由判据统一**：工具/技能/MCP 全部按"描述语义"路由，不为每类能力发明不同信号；MCP 的 description 字段恰是这个协议。
- 现状佐证：TOOLS_SCHEMA 每工具已有 description；skill_loader 已是"廉价预筛 + LLM 语义判断"两段式。

## 4. 执行顺序（先定合同，再搬部门）

① 安全（门口）→ ② 工具执行（动手段）→ ③ 上下文（眼睛/记忆）→ ④ 三间小屋 → ⑤ 出口组装。
每步：先白话设计 → owner 过目 → 动手 → 基线+测试 → 记录。
