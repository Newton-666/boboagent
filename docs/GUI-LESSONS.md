## 一、会导致功能崩盘的硬错误

### L1. 新 DOM 必须出现在 <script> 之前（2026-08-13 DESK-V2A 事故）
把 overlay-root/toast-root/confirm-overlay 追加在 `</script>` 之后 → 顶层 JS `getElementById('cf-cancel').onclick` 空指针 → **整个脚本死亡，桌面端永久卡 Connecting**。
规则：新增任何 HTML 元素，永远插入到主 `<script>` 标签之前；完工后自查"凡 JS 顶层引用的 id，DOM 必须先于 script 存在"。
回归闸：test_v2a_dom_before_script。

### L2. 静态/模拟测试 ≠ 页面真实可跑
V2A 全部测试通过但页面打不开——node 实跑只验证函数片段，不验证整体加载。
规则：GUI 票收工前，自问"如果浏览器真加载这个文件，顶层每一行会不会炸"。凡新增顶层语句（addEventListener、getElementById 赋值），确认目标元素已存在。

### L3. 测试以 HEAD 为基线会在合并后自咬
V2A 的 CSS 零改动闸门用 HEAD 做基线，合并后 HEAD 含新代码 → 测试必挂。
规则：凡"与基线比对"的测试，基线必须指向合并前固定点（rollback 标签），并处理合并前后两种状态。

## 二、审美与交互纪律（owner 原话：每个东西的摆放位置和样式都要经过思考）

### L4. 禁止 emoji 当图标直出（2026-08-13 owner 反馈"红色的 pin 太难看太显眼"）
📌 等 emoji 渲染成平台彩色大图，视觉粗暴。规则：图标一律细线 SVG（currentColor 继承文字色），默认弱色 var(--text-muted)，激活态才用品牌橙 #e8913a，危险操作仅 hover 变红。范例：PIN_SVG。

### L5. 同类控件必须成体系，禁止各自随意摆（owner："太随意就显得廉价"）
会话行内三键曾各自为政：不同字号、不同间距、删除键常红。规则：同一容器的行内操作统一一个 class 体系（参照 .act：16px 同尺寸、margin-left:2px、顺序固定 pin→改名→删除、hover 才显形）。新增行内键先进体系，不许单写内联样式。

### L6. 键盘手感是体验的一部分，不是附加功能（owner："必须点红按钮是倒车"）
弹窗替代原生 confirm 时丢了 Enter 确认。规则：任何模态/弹窗，打开即聚焦主按钮，Enter=确认、Esc=取消，与原生手感对齐后才算完成。

### L7. 摆放位置由排版地图给定，禁止自由选址
owner 会在票里/补充说明里给坐标（参照物+方位）。不确定就停下来问，不许"先放这儿试试"。

## 三、流程纪律（重复犯过的）

### L8. 汇报数字必须可复现
PERF-1 报"0/9"实际干了 248 行；LEDGER-1 报 2147 实测 2313；V2A 报"全绿"实际合并前有 2 挂。终审会独立复跑，数字对不上=返工。
规则：汇报里的每个数字，贴你本地实跑的原话输出；跑不动就如实说跑不动。

### L9. 新增样式只能从现有色板取色
token 表见 docs/GUI-DESIGN.md 第二节。引入新颜色=破坏视觉宪法，终审必打回。
