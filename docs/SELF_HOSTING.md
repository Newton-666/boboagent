# Bobo 自迭代操作手册（Self-Hosting）

> 2026-07-27 定稿。bobo 改 bobo 的规矩总集——不是放开让它改，是进厂打工：
> 任务单 → 分支实现 → 双层验收 → 人工合并。规矩一条不减。

## 三条铁律

1. **分支制**：每次任务开 `feat/xxx` 分支，**永远不许直接动 main**。
   合并权永远在用户手里。bobo 改 bobo 最大的风险不是改错，
   是改错还污染 main。

   **bobo 的停止线（2026-07-27 首秀越权后补硬，违反 = 任务失败）：**
   - ✅ 允许：在 feat 分支上工作、**在 feat 分支上 commit**、汇报
   - ❌ 禁止：`git checkout main` / `git merge` / `git push` /
     `git branch -d`——这四个动作只有用户能做
   - ❌ 禁止带脏工作区切分支（改动未 commit 就 checkout = 假分支工作）
   - 完成 = 分支上 commit 干净 + 五查汇报 + **停**。等用户审查合并。
   （首秀教训：bobo 汇报里写"等用户 merge"然后自己 merge+push+删分支，
   说好规矩又违反规矩，比不懂规矩更糟。）
2. **任务单制**：没有任务单不动手。验收标准预先写死
   （什么算"过"要可判定，禁止"看看有没有问题"）。
3. **渐进授权**：按任务分级放行，不一步到位（见下表）。

## 分工：主 bobo 执行，duo 出视角

| 场景 | 谁干 | 说明 |
|---|---|---|
| 基础修复 / 小改动 | **主 bobo 直接干** | 上下文完整、code-fix 标准自动注入、工具链全在手上。派 worker 是降配 |
| 大改动 / feature | 主 bobo 实现 + **duo B 独立验收**（或用户终审） | 需要第二双眼睛时 duo 才出动 |
| 架构决策 / 方向讨论 | **`/duo 商讨`** | A/B 对立视角出决策清单（已代码编排，确定性流程） |

duo 的位置：验收和商讨，不是执行。主 bobo 强就用主 bobo。

## 任务分级与授权

| 级 | 任务类型 | 验收强度 | 解锁条件 |
|---|---|---|---|
| L1 | 加测试、改文档、写 skill | 用户看 diff 拍板 | 已解锁 |
| L2 | 小 bug 修复（几行、单文件） | duo B 验收 | L1 连续 3 次零打回 |
| L3 | 中等 feature（多文件） | duo B + 用户终审 | L2 稳定后 |
| L4 | 架构级（engine/worker/安全分级） | **不开放自主执行**，bobo 可做但审查必须走 Cloud / Kimi / Kimi Code（2026-07-27 engine 解耦即 bobo 执行 + Kimi Code 审查） | 长期观察 |

## 自动生效的验证栈（无需提醒，已在位）

- `code-fix` 标准注入：Phase 5.5 验证五查（编译/通路/真实运行/环境一致性/证据式自报）
- 写 `.py` 自动 `py_compile`，失败带"禁止交付"警告（物理闸）
- 所有局部替换/追加显示白字色带 diff（用户可视审查）
- `pytest tests/ -q` 全绿是交付底线；打回必留测试

## 标准流程

```
1. 用户发任务（含分支名 + 验收标准）
   例："在 feat/xxx 分支上做 <任务>，验收标准：① …… ② …… pytest 全绿"
2. 主 bobo 在分支上实现（看它有没有：切分支、读文件再改、跑测试）
3. bobo 自验汇报（五查证据 + diff + 测试结果）
4. 用户审查 diff → 通过则合并 main，不通过则打回（打回点要写清）
5. 合并后重启 bobo，新代码生效（editable install，重启才加载）
```

## 打回流程

- 打回时写明：哪条验收标准没过 + 证据（文件/日志/运行输出）
- 修复后必须补对应测试（打回必留测试）
- 同一任务打回超过 2 次 → 停下来复盘是任务书问题还是能力问题，不空转

## 已知注意事项

- **改的是运行的自己**：editable install 下改动重启才生效，不会当场崩；
  最坏情况是重启起不来 → git 回滚分支即可
- **TUI 改动需构建**：动 `ui-tui/src` 后必须 `npm run build` 且
  构建产物同步到运行路径（老坑）
- **obsidian 工具在 `write_obsidian.py` / `append_obsidian.py`**，
  不是 file_writer.py（11:54 接错文件的教训：改工具前先确认注册名和调用链）
- **环境只有一份**：仓库即运行时（Single Runtime Rule，见 README）。
  没有 ~/.bobo 同步问题，没有第二副本
