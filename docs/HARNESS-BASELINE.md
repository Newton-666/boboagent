## 1. 目标（单数）：Agent 要有灵魂

Agent 越用越贴近用户的使用模式，与用户形成默契。学习信号有两个来源：
- **用户反馈**（显式：纠正、偏好、拒绝）；
- **Agent 自我反馈**（隐式：每次操作成功/出错本身是信号，用户未必察觉）。

## 2. 机制（多元，收敛同一目标）

记忆（静态存储召回）· 强化范式（动态行为更新）· 规则 / LLM 判断——**分工不互斥**。
- 记忆 ≠ 强化：记忆是"存进去、想起来才有用"（静态）；强化范式是"从结果信号改变下次怎么做"（动态）。
- 不是"只要强化不要记忆"，是不同组分用不同机制，朝同一目标。

## 3. 落点判断规则：强化范式用在"哪里"

> **强化范式适用于"答案因人而异"的决策点；不适用于"答案人人相同"的点。**

| harness 组分 | 答案性质 | 合适机制 |
|---|---|---|
| 工具选择 / 注入选择 / 记忆召回排序 / 回复风格 | 因人而异 | 强化范式 ✅ |
| 上下文组成 / 收尾闸参数 | 半因人而异 | 强化范式（带护栏）⚠️ |
| 安全（rm -rf 确认） / 诚实性（完成才说完成） | 人人相同 | 固定规则 ❌（永不学习改写） |

## 4. 动态性原则（轴）：一切为动态流通过程

记忆、上下文处理、工具调用——**都应是动态处理过程，不是静态处理**。
- 记忆是"动态流通"的过程（不是存了就完，而是持续流动、被使用、被修正）；
- 上下文是自适应组成（不是固定注入）；
- 工具调用是自适应选择；
- **只有动态，Agent 才可能学习用户习惯**——静态是学习的天敌；动态 = 环路存在且携带学习。

## 5. 护栏（防止灵魂长歪）

- **结果验证**：学习信号用"结果确认"（按新行为做后是否更顺），不用单次反馈确认；
- **累积阈值**：同一信号重复出现才固化为行为（一次不算，三次才算）；
- **可逆**：学错的行为可撤销（灵魂能长歪，也能修回来）。

## 6. 派生设计原则（harness 改造优先级）

- 优先给"因人而异"的决策点装**反馈通道**（工具选择/注入选择/记忆排序/回复风格）；
- "人人相同"的点保持规则化；
- 统一窗口（骨干通信）设计时，**每条合同自带反馈通道**——让每个枢纽可被观察、被奖励。

## 7. 范式细化条款（2026-08-23 定）

1. **学习 = 后端背景监督，非 LLM 管辖**（owner：LLM 不会可靠地自我学习——正则错它不会自己去记忆模块记；学习 100% 在后端确定性代码，LLM 是被监督的演员）。
2. **信号只作输入，不作方向盘**（owner：不喜欢信号驱动 harness——不确定性大；前馈路径永远 description+规则驱动，信号只是学习的肥料）。
3. **description（铭牌）静态不动**（作者写的包身份；学习不改写它，避免污染语义）。
4. **RL 本质 = 后端"观察→累积→落笔"闭环，落笔两处**：
   - 写记忆（用户偏好/事实/规则）← 用户反馈为主（灵魂）；
   - 沉淀新技能包（重复模式→新技能模块）← 自我反馈为主（能力自进化）。
5. **动态性**：记忆/上下文/工具调用一切动态流通，静态是学习天敌。
