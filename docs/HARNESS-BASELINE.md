## 1. 目标（单数）：Agent 要有灵魂

Agent 越用越贴近用户的使用模式，与用户形成默契。学习信号有两个来源：
- **用户反馈**（显式：纠正、偏好、拒绝）；
- **Agent 自我反馈**（隐式：每次操作成功/出错本身是信号，用户未必察觉）。

## 2. 机制（多元，收敛同一目标）

记忆（静态存储召回）· 强化范式（动态行为更新）· 规则 / LLM 判断——**分工不互斥**。
- 记忆 ≠ 强化：记忆是"存进去、想起来才有用"（静态）；强化范式是"从结果信号改变下次怎么做"（动态）。
- 不是"只要强化不要记忆"，是不同组分用不同机制，朝同一目标。

## 3. 落点判断规则：强化范式用在"哪里"

> **强化范式适用于"答案因人而异"的决策点；不适用于"答案人人相同"的点。**

| harness 组分 | 答案性质 | 合适机制 |
|---|---|---|
| 工具选择 / 注入选择 / 记忆召回排序 / 回复风格 | 因人而异 | 强化范式 ✅ |
| 上下文组成 / 收尾闸参数 | 半因人而异 | 强化范式（带护栏）⚠️ |
| 安全（rm -rf 确认） / 诚实性（完成才说完成） | 人人相同 | 固定规则 ❌（永不学习改写） |

## 4. 动态性原则（轴）：一切为动态流通过程

记忆、上下文处理、工具调用——**都应是动态处理过程，不是静态处理**。
- 记忆是"动态流通"的过程（不是存了就完，而是持续流动、被使用、被修正）；
- 上下文是自适应组成（不是固定注入）；
- 工具调用是自适应选择；
- **只有动态，Agent 才可能学习用户习惯**——静态是学习的天敌；动态 = 环路存在且携带学习。

## 5. 护栏（防止灵魂长歪）

- **结果验证**：学习信号用"结果确认"（按新行为做后是否更顺），不用单次反馈确认；
- **累积阈值**：同一信号重复出现才固化为行为（一次不算，三次才算）；
- **可逆**：学错的行为可撤销（灵魂能长歪，也能修回来）。

## 6. 派生设计原则（harness 改造优先级）

- 优先给"因人而异"的决策点装**反馈通道**（工具选择/注入选择/记忆排序/回复风格）；
- "人人相同"的点保持规则化；
- 统一窗口（骨干通信）设计时，**每条合同自带反馈通道**——让每个枢纽可被观察、被奖励。

## 7. 范式细化条款（2026-08-23 定）

1. **学习 = 后端背景监督，非 LLM 管辖**（owner：LLM 不会可靠地自我学习——正则错它不会自己去记忆模块记；学习 100% 在后端确定性代码，LLM 是被监督的演员）。
2. **信号只作输入，不作方向盘**（owner：不喜欢信号驱动 harness——不确定性大；前馈路径永远 description+规则驱动，信号只是学习的肥料）。
   **精确定义（Pi 评审 2026-08-24 写死）**：方向盘 = 前馈决策逻辑与 description（不可动）；
   **权重 = 排序/打分（可学）**——记忆召回排序、工具广告优先级属权重，可经学习环更新；
   决策逻辑（走哪条路、读什么判断）与 description 属方向盘，永不学习改写。
   **通道区分**：反馈通道分两种——**观察通道**（记录信号，不改决策，所有部门可装，
   含安全/收尾）与**奖励通道**（改权重，只装"因人而异"部门）。安全/收尾只装观察，
   永不装奖励——否则条款一被破。
3. **description（铭牌）静态不动**（作者写的包身份；学习不改写它，避免污染语义）。
4. **RL 本质 = 后端"观察→累积→落笔"闭环，落笔两处**：
   - 写记忆（用户偏好/事实/规则）← 用户反馈为主（灵魂）；
   - 沉淀新技能包（重复模式→新技能模块）← 自我反馈为主（能力自进化）。
5. **动态性**：记忆/上下文/工具调用一切动态流通，静态是学习天敌。
6. **模块化 = 路由与生命周期的共同前提**（owner：衰减/替换/合并都作用在"单元"上——LLM 做不了生命周期，后端也做不了，除非知识是离散可寻址带元数据的模块；没有模块，路由和遗忘都无从谈起）。
7. **知识生命周期（写 + 忘双端闭合）**：落笔不是终点——衰减（过时降权）/ 替换（等价判断）/ 合并（相似归并，同模式强化不新建）/ 剪枝（超容量驱逐）+ 验证（长期未用判死重）。没有生命周期，100 天后系统自退化。
8. **判断权归 LLM，约束是过渡期拐杖（2026-08-25 owner 定）**：
   - **判断主体 = LLM**：什么值得沉淀/更新/归类（skill 判定、记忆归类、排序打分）这类"语义理解判断"交给 LLM——"用户这句话是偏好还是纠正"、"这模式还会不会再出现"，确定性规则做不完美，LLM 天然擅长。
   - **约束是拐杖，不是方向盘**：现阶段 LLM 判断未完全成熟，必须给约束/引导（负向清单、更新优先级、类级命名、数量门卫）纠正偏差；约束保证判断相对准确，**不是**永久替代 LLM 判断。
   - **约束必须可拆除**：每个约束是独立模块、带 A/B 验证条件；随 LLM 能力提升逐步松绑（数量门卫 3→2→1→仅留负向清单；负向清单可硬拦截→降级为提示）。呼应"补偿型约束可单独拆除"。
   - **与条款 1 的边界（不冲突）**：条款 1"学习 = 后端背景监督"指**学习动作**（累积、落笔、生命周期 = 确定性代码）；本条指**判定标准**（值不值得、归到哪、怎么命名 = LLM + 约束）。判断交给 LLM（带约束），落笔留在后端（可测、可审计、可回滚）。模型每几个月能力提升，判断约束逐步松绑；落笔仍留后端。
   - **演进方向**：未来越来越依赖 LLM 自身能力做判断，约束随时间衰减——现在约束多一些，未来判断多一些，收敛方向始终是 LLM 能力。
