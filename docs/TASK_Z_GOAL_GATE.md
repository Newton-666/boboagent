# 票 Z：收工闸 v2 — 事没做完不许停

**优先级**：高（用户核心诉求 2026-07-29："没做完之前都不要停，做完就得停"）
**风险**：中（动收工逻辑，误拦会导致死循环——熔断器是生命线）
**分支**：`feat/goal-gate` ｜ **禁止**：merge / push，完成后五查汇报 + git status 原文等 Kimi 终审
**开工铁律**：`git branch --show-current` 先行；commit 后 `git checkout main` 归位。

---

## 一、需求（用户原话语义化）

回合结束（机械节拍）≠ 事情做完（语义目标）。规则：
- **没做完**：引擎禁止收工，回注继续（现有台账闸的延伸）
- **做完了**：必须停，禁止空转（熔断器保证）
- **用户打断权至上**：用户发新消息/cancel 随时可截停，收工闸不得对抗用户

## 二、现状与缝

现有票 K 收工闸：台账有 pending 项 → 回注（最多 2 次）→ 熔断放行 + ⚠️ 提示。

三条缝：
1. **无账裸奔**：工作回合没建台账 → 闸完全失效（如 10:50 "现在跑测试"早退案）
2. **口头承诺型早退**：最后一条回复含"我将继续/接下来我会/现在跑/稍等"类未来时承诺，但回合收了
3. **假销账**：台账全标 done 但实际没做（LLM 自己打分不可靠）——本票只检测，不深究

## 三、处方

### 1. 无账工作回合强制建账（补缝 1）
- 回合进入第 2 个工具轮且台账为空 → 引擎在 tool_result 后注入一条 system 提醒："检测到多步任务但未建台账，请立即用 task_ledger 建账再继续"
- 已有 _worker_reminded 的先例（engine.py ~590 行），照此模式
- 纯问答/闲聊回合（工具轮 < 2）不触发

### 2. 承诺检测闸（补缝 2）
- 回合即将 DONE 时，扫描最后一条 assistant 回复，命中未来时承诺模式且本轮台账有 pending 或本轮无台账但有工具调用：
  - 模式清单（正则）：`(我将|我会|让我|接下来|下一步|稍后|一会|待会).{0,10}(继续|执行|运行|跑|处理|完成|修复|修改|测试)` / `(现在|马上|这就).{0,6}(跑|执行|运行|开始)`
  - 命中 → 视同台账未完成，走回注路径（计入同一个 _ledger_reinject_count 熔断计数）
  - **白名单防误拦**：回复中含"已完成/全部完成/测试通过/已交付"等收束语时不拦（承诺与收束并存时，信收束）
- 误拦代价 = 多一轮 LLM 调用；漏拦代价 = 用户再发一次"继续"。**宁可误拦，但熔断器 2 次必放行**

### 3. 熔断放行必须留痕（现有逻辑的强化）
- 熔断放行时除了 ⚠️ 文案，写事件总线 `goal_gate.released`（含 pending 项数、回注次数）
- 承诺检测命中写 `goal_gate.promise_detected`

## 四、红线

- 熔断器（2 次回注必放行）**一个字节都不许动**——它是死循环保险丝
- 用户中断路径（_interrupt_event）优先于一切闸门
- 闲聊回合零影响（无工具调用直接放行）

## 五、验收标准（真撞闸）

1. **复刻 10:50 案**：FakeLLM 第一轮回复"现在跑测试"（无工具调用）→ 闸命中 → 回注 → 第二轮真跑 → 才 DONE
2. **无账强制建账**：3 个工具轮无台账 → history 中出现建账提醒
3. **熔断逃生**：连续 3 轮承诺不兑现 → 第 2 次回注后放行 + ⚠️ + goal_gate.released 事件
4. **闲聊零误拦**："谢谢"回合直接 DONE，无闸触发
5. **收束白名单**："测试已全部完成，明天可以继续优化"（承诺词+收束词并存）→ 放行
6. 全量 pytest 基线 1145 passed / 2 skipped 不回归
7. 改了 core/，五查第 6 项必填"是"
