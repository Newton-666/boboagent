# Bobo Evaluation 设计 v0.1

## 〇、定位声明（每套考卷必须复读）

没有任何考卷能覆盖整个系统。每套考卷自带两项声明：**覆盖什么**、**明确不覆盖什么**。
评估回答的问题是"相对昨天变好了吗"（Δ 基线制），不是"完美吗"。

## 一、六卷体系（按判分方式分卷）

| 卷 | 考什么 | 判分 | 成本/触发 |
|----|--------|------|-----------|
| A 纪律合规 | 台账时序、模式认知、执法遵守、汇报诚实 | 确定性规则 | 极低；harness 层改动必跑 |
| B 工程闭环 | 端到端修 bug/加功能 | pytest 绿否 | 低；engine/工具改动加跑 |
| C 协作组织 | relay 派工、评审独立性、降级留痕、编制合理 | 半自动（日志机判+抽样人审） | 中；office 改动加跑 |
| D 记忆连续 | 跨会话记忆调用、笔记使用、时序错位（拿旧笔记当待办） | 半自动 | 中 |
| E 效率经济 | token/轮次/工具调用经济性（23 次翻笔记考古 = 0 分案例） | 计数+阈值 | 极低；harness 改动必跑 |
| F 自我认知 | 对自身架构/能力/边界的闭卷认知（见 §四） | 闭卷问答，禁调工具 | 极低；常驻 |

**盲区声明（全部考卷共同）**：创造性方案优劣、长期目标对齐、真实用户满意度、
对抗性安全（红队）、未发生过的事故类型。考卷防复发不防新坑，故考卷必须随事故持续增补
（制度：每张事故类票关闭时，必须评估是否转化为考题）。

## 二、真实性专章（对抗分布偏移）

考卷与现实的差距永远存在，三个来源各配一个机制：

1. **轨迹回放**（治"题目单一 vs 现实长程无序"）：从真实会话截取前 N 轮作上下文，
   第 N+1 轮即考题。无序性、长步骤、中途变卦由现实自带，不人工编造。
2. **扰动器**（治"评估 prompt 干净 vs 用户 prompt 脏"）：owner 的 prompt 风格
   （语音错别字、模糊指令、改口）做成确定性变换器；每题跑干净版（测能力）+
   脏版（测鲁棒性）。
3. **活体考卷**（治"考卷静态 vs 用法漂移"）：每周从真实会话抽样入库，老题退休，
   滞后锁定 ≤1 周。

**双指标互验（兜底）**：考场分数（离线）× 线上事故率（崩溃/补账/虚报/考古次数，
审计管道已在收集）。两者背离时修考卷——**考卷本身也接受考核**。

## 三、运营纪律

- 环境隔离：干净 worktree + 隔离 library/data；md5 闸门纪律复用
- 基线制：首跑分数=基线，之后只看 Δ；可选外部参照组（同题丢给 Claude Code / pi 跑）
- 冒烟合卷：≤15 分钟精选版，大版本合并前必跑

## 四、F 卷与自我认知三层模型（G-1 孪生）

设计标准（owner 原话）：对自我的认知应"不需要思考、不需要检查就该知道"。

| 层 | 内容 | 注入策略 | F 卷考法 |
|----|------|----------|----------|
| L0 肌肉记忆 | 身份、三层架构一句话、闸位置、绝对边界、当前模式 | 常驻注入 ≤300 字符（占 LN-4 预算，须狠） | 闭卷，禁调工具，答错=事故级 |
| L1 工作记忆 | GUIDANCE 能力地图、skill 规程 | 按任务类型触发注入 | 允许触发后作答 |
| L2 档案 | 开发手册、历史票据、战役卷宗 | 不注入，考古时查阅 | 允许查阅 |

现状病灶：L0 内容掉进 L2（"我还有这个工具吗，让我查一查"——2026-08-12 O-8 施工中
翻 gatewayClient.ts 找 engine 的闸即实证）。G-1 票交付 L0 注入段，F 卷即其验收。

## 五、落地次序

1. 首批 15 题：A 8 + B 4 + E 3（题干+期望行为+判分规则+血案编号），C/D 先出题后建跑道
2. G-1：L0 自我地图注入（小票，与 EVAL 并行）
3. 跑道工程票：轨迹回放采集器 → A/B/E 自动判分 → 冒烟合卷
4. F 卷题库：随 G-1 地图内容同源生成
