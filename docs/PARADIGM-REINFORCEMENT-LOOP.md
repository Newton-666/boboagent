# 范式思考：环路学习（Parked Proposal · 2026-08-23）

> 状态：**暂定提议，不实现**。owner 观点可能随时间演化，本文档是思考锚点。
> 背景：owner 明确——**不翻新 harness**（当前能用、好用、长期运行验证过）；本提议只关乎"思考范式"。
> 核心判断：**当前 harness 不形成一个真正的学习环路**——跑完就完，没有从经验中变强的机制。

---

## 1. 提议（owner 原话要点）

- 当前很多 Agent 的"以后别这么干"= 写进 memory——**这本质不是强化学习**（是检索；下次可能还犯同样的错）。
- 提议：**在失败点立刻进行强化**——例如工具调用出现正则问题时，**立刻**形成行为修正，而不是"存起来等它想起来"。
- 真正的 RL（权重更新）是重家伙，且与"基础模型每月换代"前提冲突（策略追移动靶）。owner 提议的是更轻的形态。

## 2. 中间形态候选："失败点反射"（point-of-failure reflex）

| 特征 | 机制 |
|---|---|
| 即时 | 失败那一刻记录"错误模式 + 正确姿势"，注入**下一次调用**上下文（非永久记忆） |
| 可测 | 记录错误模式后续 N 次复现率；复现率下降 = 反射生效 |
| 自动过期 | N 次无复现 → 修正自动撤销（**不变成永久硬编码**，契合"不为当前模型加固"） |

满足三条理念：不是被动 memory、不是 weight-RL、不会随模型换代变死重。

## 3. 与既有原则的关系

- 与"补偿型约束可拆除可测量"一致：反射是**有生命周期的临时约束**，天然可拆除；
- 与"默认信任模型"一致：只在失败点介入，不预先加规则；
- 与"先砌墙后搬房"一致：若实现，作为 harness 的一个新"部门/合同"接入，而非塞进 engine。

## 4. 待议问题（后续讨论可演化）

- 反射的注入位置：下一次调用上下文 vs 专门的反省环节？
- 复现窗口 N 的取值与度量方式（复用 B26 的调用数基线？）
- 是否与沉淀/记忆系统合并，还是独立环路？
- 未来模型变强后，反射是否自动退化为零（正确性如何验证）？
