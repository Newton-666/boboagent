# 活体知识库四问

> 来源：2026-07-31 用户 × Kimi 定稿，宪法第十七章实施细则

## Q1 数据库怎么管：按内容，不按时间

混乱的根源不是笔记多，是"同主题散落多篇"。铁律：

1. **一主题一笔记**。同主题的新信息永远更新旧笔记，不新开会话笔记。
   库会涨的是字数不是篇数，这是防混乱的第一闸。
2. **时间是元数据，不是结构**。文件夹按领域分（`agent开发/`、`电商调研/`、
   `生活/`），日期只活在 frontmatter（created / last_touched / source_sessions）。
3. **bobo 自维护索引**：`index.md` 是图书馆目录，每次写笔记同步更新，
   用户打开库第一眼看到的是地图不是书堆。
4. **定期整理并入夜班体检**：孤儿笔记、疑似重复主题、90 天未触达笔记，
   体检报告里列出来，合并/归档动作要 diff 预览 + 确认（防污染原则 1）。

## Q2 文档怎么起名：主题短语，人话，稳定

- **格式**：≤12 字主题短语，用对话语言（中文对话起中文名）——
  `CRMEB 试炼.md`、`bobo 定位.md`。
- **禁止**：日期前缀、session id、uuid、下划线机翻风。时间是 frontmatter 的事。
- **同名检查**：起名前先查库——同主题 → 更新旧笔记；真新主题 → 新建。
  判断"是否同主题"错判的代价：误并 > 误分（误分体检能发现，误并毁笔记），
  拿不准就新起并在体检中标记疑似重复。
- **一旦命名，永轻改**：改名断链接。必须改时同步改 index 和所有引用。

## Q3 知识库与记忆（v5_memory）怎么配合：指针制，不复制

| | v5_memory（闪念层） | 主题笔记（知识库） |
|---|---|---|
| 形态 | 原子条目：事实/偏好/教训 | 结构化主题文档 |
| 用途 | 会话开始时注入 prompt，"该想起什么" | 需要深潜时按需读取，"去哪查细节" |
| 流向 | 主题笔记里稳定的结论**蒸馏晋升**为 memory 条目 | memory 条目带**指针**（笔记路径+段落），不复制内容 |
| 防重 | 晋升时查重；笔记改写后相关条目跟着更新或失效 |

一句话：**memory 是索引卡，知识库是书架**；卡片上写"去哪本书哪页"，
不抄书。

## Q4 上下文压缩与知识库怎么配合：压缩=转移，不是遗忘

这是四层咬合最关键的一环：

1. **压缩前先蒸馏**：触发压缩时，先把本轮新结论写进主题笔记，
   再走归档。于是压缩从"有损丢弃"变成"转移至知识库"——
   敢压了，压缩阈值可以压得更低，上下文更轻。
2. **反向注入**：新会话开场不塞历史原文，按用户输入检索相关主题笔记
   的**摘要段**注入。比 v5_memory 注入更大的知识单元，
   比塞原文省得多。
3. **闭环**：对话 → 主题笔记 →（下次对话）按需注入 → 压缩前先蒸馏 →
   知识库越滚越准，上下文越跑越轻。

配套规则：注入的主题笔记摘要段必须带出处标记，
LLM 引用后走 citation 加分（现有机制直接复用）。

## Q3 补：MEMORY.md 双向镜像（2026-07-31 用户拍板）

记忆条目（knowledge_base.json）配一个活人可读写的 md 镜像，**双向同步**。

### 形态

- 单文件 `MEMORY.md`，放知识库根目录，按 type 分小节
- 每条记忆一行，带稳定锚点（锚点 = JSON 的 id）：

  `- [#42] 用户偏好用中文交流 (knowledge · 2026-07-20 · 信号 85)`

- 覆盖 = 按 #id 替换该行；删除 = 移除该行；新增 = 追加。
  映射确定性，禁止模糊匹配。

### 同步规则

1. **JSON→md**：bobo 侧任何记忆写操作（add/覆盖/删除/信号分变动）
   后立即重生成镜像。生成是幂等全量重写，不做增量 patch。
2. **md→JSON**：bobo 启动时比对 mtime——md 比 JSON 新说明用户手改过，
   解析 md 回 JSON。用户手改优先（宪法防污染原则 2：人手修订最高）。
3. **保守降级**：md 解析失败（格式被改坏）→ 跳过导入并告警，
   宁可不同步也不毁 JSON。导入前自动备份 knowledge_base.json.bak。
4. 用户手改导入的条目打上 `human_edited: true`，bobo 后续
   自动演化（信号分衰减、草稿归档）对这类条目降级或豁免。

### 与主题笔记层的关系

MEMORY.md 镜像是**闪念层的透明面**；主题笔记仍是独立层。
蒸馏晋升规则不变：主题笔记稳定结论 → memory 条目 → 自动出现在
MEMORY.md 里。用户看到的图景：MEMORY.md（卡片盒）+ 主题笔记（书架），
全部可读可改。

## 库址（2026-07-31 用户拍板）

**`<项目根>/library/`——一级文件夹，禁止嵌套。**

- `library/MEMORY.md`（记忆镜像）
- `library/index.md`（图书馆目录）
- `library/<领域>/<主题>.md`（主题笔记）
- 不放在 data/、docs/ 或任何子目录下——它是用户资产，不是系统配置
