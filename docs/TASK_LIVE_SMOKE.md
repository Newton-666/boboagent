# TASK：活体冒烟测试（Live Smoke Harness）

> 级别：L3（duo B 验收 + 用户终审）
> 分支：feat/live-smoke-harness
> 来源：2026-07-28 用户拍板——"测试分两种：静态 pytest 绿 + 更重要的是 bobo 能启动并且运行程序"。本票是 L2 活体验证的基础设施，也是 HTTP 400 崩溃案"凶手未抓到"的主动围猎网。

## 目标

新建 `scripts/smoke_boot.py`（或 tests/ 外独立脚本）：**真实启动 bobo 进程，驱动一轮真实对话，验证五联征**。静态测试全绿但进程起不来的事故（如 `_skill_mgr` 断链导致注入静默失败）由此兜底。

## 五联征（全部满足才算 PASS）

1. **ready**：进程启动，TUI 出现 ready 提示（或 backend 模式就绪标记），启动耗时有上限（如 ≤15s）
2. **握手**：发送一条无需工具的简单提问（如"用一句话回答：1+1等于几"），收到模型真实回复
3. **工具一轮**：发送一条必触发工具的指令（如"执行终端命令 echo smoke_ok"），观察到工具调用 + 结果 + 总结回复
4. **日志干净**：运行期间 `data/logs/bobo.log` 无新增 ERROR/Traceback（已知白名单除外，白名单写在脚本顶部注释）
5. **退出干净**：正常退出指令后进程在限定时间内结束，退出码 0，无僵尸线程/子进程残留

## 实现要点

- 用 `pexpect`（或 pty 标准库）驱动 TUI；若 TUI 驱动不稳定，可用 backend 模式先行，TUI 模式作为二期
- 真实 API 调用（用当前配置的 provider），因此该脚本**不进 pytest 默认集**，独立运行：`./.venv/bin/python3 scripts/smoke_boot.py`
- 运行前快照 bobo.log 行数，运行后只 diff 新增部分
- **数据隔离铁律适用**：脚本产生的会话/记忆写入须可清理或可指定临时数据目录，禁止污染真实 data/

## 二期（本票不做，仅记录）：故障注入

- 对话中途发 SIGINT / SIGTERM / 关闭 pty，观察崩溃姿态与日志留证质量
- 目标：主动复现 HTTP 400 崩溃案的凶手（信号源）

## 验收标准

1. 五联征全部通过，脚本输出逐项 PASS/FAIL + 证据（耗时、日志 diff 摘要、退出码）
2. 脚本可重复运行，三次连续 PASS
3. pytest 全量绿不受影响（脚本不进默认集）
4. 五查汇报；feat 分支；本地 merge 前等用户确认

## 边界

- 不修改 engine/TUI 任何源码；发现活体问题只记录上报，修复另立票
- 真实 API 调用花费极小（两条短消息），但脚本须支持 `--dry`（跳过 LLM，仅验证启动+退出）
