## §1 范式层（理念/出发点）

### 1.1 目标（单数）：Agent 要有灵魂
Agent 越用越贴近用户使用模式，形成默契。学习信号两个来源：**用户反馈**（显式）+ **Agent 自我反馈**（隐式：每次操作成败本身是信号）。

### 1.2 机制（多元，收敛同一目标）
记忆（静态存储召回）· 强化范式（动态行为更新）· 规则/LLM 判断——分工不互斥。

### 1.3 落点判断规则
**强化范式适用于"答案因人而异"的决策点；不适用于"答案人人相同"的点**（安全/诚实——永不学习改写）。

### 1.4 范式细化条款（七条）
1. **学习 = 后端背景监督，非 LLM 管辖**（LLM 是演员，学习 100% 在后端确定性代码）；
2. **信号只作输入，不作方向盘**（前馈路径永远 description+规则驱动）；
3. **description（铭牌）静态不动**（作者写的包身份，学习不改写）；
4. **RL 本质 = 后端"观察→累积→落笔"闭环**，落笔两处：写记忆（用户反馈为主）+ 沉淀新技能包（自我反馈为主）；
5. **动态性**：记忆/上下文/工具调用一切动态流通，静态是学习天敌；
6. **模块化 = 路由与生命周期的共同前提**（衰减/替换/合并作用在物理单元上）；
7. **知识生命周期（写+忘双端闭合）**：衰减/替换/合并/剪枝/验证——没有生命周期，100 天后系统自退化。

### 1.5 护栏（防灵魂长歪）
结果验证 · 累积阈值（一次不算三次才算）· 可逆（学错能撤销）。

## §2 宏观层（组分拆分与排列）

### 2.1 骨干通信：统一窗口模式
所有部门连接统一为"走廊递简报+申请 → 部门答结果 → 走廊决定"。禁止其他接法。

### 2.2 能力层：挂包协议 + 描述即路由判据
- 工具/技能/未来 MCP = 统一挂包；**每个包铭牌 = 高质量 description**（服务什么/何时用/何时不用）；
- **路由两段**：① 廉价预筛（关键词/类型，只为省钱缩小候选，非路由本身）；② 语义判断（读 description × 任务意图 → 激活谁）；
- 描述质量 = 路由准确率杠杆（一等公民）。

### 2.3 宏观设计原则：默认休眠，路由激活（MoE 类比）
组分默认不进入上下文，由路由器按"任务×用户"激活；固定底座（身份/状态）除外。路由器 = 适配层（灵魂）的家。

见 §3。

## §3 完整 Loop（决策树 + 学习环 + 生命周期）

### 3.1 主循环（一回合，前馈，决策树）
```
用户输入 → [入口] GOAL/任务类型
  → [上下文组装] 固定底座 + 路由器①记忆召回（模块化选）+ 路由器②能力清单（挂包两段）
  → [LLM] 读路由后上下文（description 驱动，纯演员）
      ├ 工具 → [安全门口]（确定性）→ [执行] → 结果
      └ 文本 → [收尾闸链]（确定性）→ [出口] → 输出
```

### 3.2 学习环（跨回合，后端背景监督）
```
[观察]（全程：从 LLM 被调用起，每个结果点）→ [分类] → [累积(过阈值)]
  → [落笔] 写记忆 / 沉淀新技能包
  → [生命周期] 衰减 / 替换 / 合并 / 剪枝+验证（作用在物理模块单元）
  → 下一轮[上下文组装]路由更准
```

### 3.3 边界
- 学习环只包"因人而异"的路由器①②；安全/收尾（人人相同）在学习环外，永不学习改写；
- 信号不进前馈；description 不动；LLM 不负责学习。

## §4 三挂包的物理模块现状（模块 = 独立文件/文件夹）

| 挂包 | 现状 | 模块度 |
|---|---|---|
| 技能 | `data/skill-standards/<技能>/standard.md`（每技能一文件夹） | ✅ 文件夹级 |
| 工具 | `tools/<工具>.py`（每工具一文件） | ✅ 文件级 |
| 记忆 | v5_memory.py + 单 JSON 存储（六类混存） | ❌ **物理未模块化**——无法对单元做生命周期 |

**差距**：记忆需物理拆分为独立模块（画像/事实/规则/教训，各独立存储单元 + 元数据）。

## §5 开放问题（评审重点——设计意图 vs 可验证性）

1. **记忆物理模块化的边界**：四个模块（画像/事实/规则/教训）的划分是否成立？元数据 schema 应包含什么？
2. **工具功能域簇**：工具已文件级模块，是否需要簇文件夹（`tools/file/` 等）支撑簇级生命周期？还是单工具文件已够？
3. **学习环的观察粒度**：观察从"LLM 被调用"起全程持续——具体观察点（意图/决策/执行/收尾/用户反馈）的信号 schema 是什么？
4. **生命周期触发**：衰减的时间尺度？合并的相似判定（语义签名）？剪枝的容量上限？
5. **路由器①②的接口**：输入（任务类型/GOAL/用户）× 输出（激活的模块集）——首版用规则实现还是直接上适配层？
6. **与现有系统的衔接**：v5_memory 迁移到物理模块化，对现有测试/沉淀/记忆工具的影响面？
