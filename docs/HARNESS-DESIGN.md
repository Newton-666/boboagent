## §1 范式层（理念，简述——详见 BASELINE）

- 目标：Agent 要有灵魂（越用越贴近用户，用户反馈 + 自我反馈双信号）；
- 机制多元：记忆（静态存储）· 强化范式（动态行为更新）· 规则——收敛同一目标；
- 落点规则：强化范式用于"答案因人而异"处；"人人相同"处（安全/诚实）永不学习改写；
- 七条细化：学习=后端监督非LLM · 信号只作输入不作方向盘 · description 静态不动 · RL=观察→累积→落笔（写记忆/沉淀技能）· 动态性 · 模块化=路由与生命周期前提 · 知识生命周期（写+忘双端）；
- 方向盘边界（Pi 写死）：**前馈逻辑与 description 不可动；排序/打分权重可学**；
- 通道二分（Pi）：**观察通道**（全员可装，含安全）vs **奖励通道**（仅因人而异部门）；安全/收尾只装观察。

## §2 宏观层（组分与排列）

### 2.1 骨干通信：统一窗口模式
所有部门连接统一为"走廊递简报+申请 → 部门答结果 → 走廊决定"。

### 2.2 三挂包（能力层）——模块（物理单元）与类别（池管理）

| 挂包 | 模块（物理单元） | 常驻/可变 | 类别（池管理） |
|---|---|---|---|
| **记忆** | 六类存储单元（USER_PREF/RULES/FACT/ACHIEVEMENT/LESSON/GOAL） | 常驻记忆（画像核心，极小）+ 可变记忆（路由召回） | 不设类别（六类即单元） |
| **工具** | 每工具一文件 | 常驻工具（极小集，每轮广告）+ 可选工具（大池，休眠） | domain 元数据（文件/终端/网络/知识库/通信/版本/记忆/计算机操作）——预筛定位 |
| **技能** | 每技能一文件夹 | **全部可变**（沉淀池，休眠，MoE 路由激活） | 代码/写作/研究/办公/生活…（**每类独立上限，总量上限 N**） |

### 2.3 默认休眠，路由激活（MoE）
组分默认不进入上下文，路由器按"任务×用户"激活；固定底座（身份/状态/常驻工具/常驻记忆）每轮必带且要薄。**沉淀 1000 个技能也不贵——激活才付费（库存成本 0，激活 ≤ 路由预算）**；但**池子仍设上限**（MoE 解决"激活才付费"，分类管理解决"池子限规模"）。

### 2.4 技能 = 语言工作流（无工具声明）
技能包 = **description（何时用）+ 流程语言（怎么做，步骤/最佳实践）**——**不声明工具**。
工具路由 = **广告范围**（常驻 + domain 预筛候选池）+ **LLM 语义配对**（读流程语言 × 工具描述，运行时完成）。
依赖顺序：**任务 → 技能（流程语言）→ LLM 配工具 → 记忆横切支撑**；无技能命中 → 工具按 domain 直接路由（兜底）。

## §3 完整 Loop

```
┌ 主循环（一回合，前馈，决策树）───────────────────────────────────────┐
│ 用户输入 → [入口] GOAL/任务类型                                       │
│   → [上下文组装]                                                     │
│       ├ 固定底座（身份/状态/常驻工具/常驻记忆）——每轮必带，薄           │
│       ├ 路由器① 记忆召回：任务 → 六类单元 → 描述语义 → 选              │
│       ├ 路由器② 能力清单：                                           │
│       │   技能：类别预筛 → description → 激活工作流（1-2 个）          │
│       │   工具：按 domain 预筛候选池 →（LLM 读流程语言配工具）         │
│       └──► [LLM] 读路由后上下文（description 驱动，纯演员）           │
│            ├ 枢纽①：工具 or 文本                                     │
│            │  ├ 工具 → [安全门口] → [执行] → 结果                     │
│            │  └ 文本 → [收尾闸链] → [出口] → 输出                     │
│            └──► 结果（全程观察：LLM 调用起每个结果点）                 │
└───────────────┼─────────────────────────────────────────────────────┘
                ▼
┌ 学习环（后端背景监督，跨回合）───────────────────────────────────────┐
│ [观察]（决策点×结果 schema，挂 event_bus）→ [分类] → [累积(≥3 次)]      │
│   → [落笔] 写记忆（可变记忆六类单元）/ 沉淀技能（按类别进休眠池）        │
│   → [生命周期]（写+忘双端，作用于模块，按类别管理）                     │
│      衰减(LRU: last_used) / 替换(等价检测) / 合并(保守)                │
│      剪枝（超类别上限→剪该类最久未用；超总量→瘦身）                     │
│      验证（被路由且有效→晋升；长期未路由→判死重可回收）                 │
│   → 下一轮路由更准（激活仍 ≤ 预算）                                   │
└──────────────────────────────────────────────────────────────────────┘
```

**边界**：安全/收尾在学习环外（只观察不奖励）；信号不进前馈；description 不动；LLM 不负责学习。

## §3b 沉淀机制设计方向（2026-08-24 定）

1. **触发 = agent 自主判断**（替代从未成功的 count-based：同模式≥3 从未触发过——次数不成立）。agent 判断"这值得沉淀成技能"时创建；判定标准待细化。
2. **生命周期 = 使用驱动**（基于"最后使用时间"，非创建年龄）：active → stale → archived 状态机；长时间未用 → stale；更久 → 归档（可逆，不删除）；再用 → 自动 reactivate。
3. **保护**：用户显式钉住（pinned）的技能永不自动改动；新技能时间锚定（防刚创建就被误杀）。
4. **纯确定性实现**：生命周期状态转换无 LLM（符合"学习=后端监督"）；仅创建判定可考虑轻量规则。
5. **Provenance 跟踪**：只管理"自主沉淀"的技能；内置/外部技能不自动改。

### 与已建组件衔接
- 触发判定：C 观察总线的累积信号可作为创建候选来源（agent 自主决定的输入）；
- 生命周期判据：last_used（A1 已补字段）= 使用驱动地基；
- C3 已有剪枝归档，补 stale 中间态 / pinned 保护 / 时间锚定。

## §3c 上下文压缩设计（2026-08-24 owner 定）

### 验收标准（owner）
压 5-6 次后，用户问"还记得X吗" → bobo 必须能答出来。压缩不仅要压，还要**知道压什么**。

### 两层分离（关键澄清）
- **保存层（durability）**：用户提及的重要事实必保存（压多次不丢）——必保层；
- **注入层（routing）**：X 平时休眠（MoE 默认休眠），相关任务或"还记得X吗"时被路由召回注入——按需激活。
- **无条件保存，按需注入**——不冲突，是两层。

### 必保层准入（漏斗，非仅关键词）
1. **显式信号**（关键词快路径）：记住/我喜欢/以后/别忘了 → 必保；
2. **硬事实规则**（确定性）：代码/数字/路径/具体名字/决策结论（决定/改成/选）→ 规则识别必保；
3. **LLM 语义兜底**：扩展现有 _precipitate_memory——"这段里有用户在意的事实吗"，防漏网。

保证：重要内容必被保护，不因缺关键词而丢。

### 闭环路径
压缩时 X → 必保层沉淀进记忆（保存层）→ 平时休眠（注入层不召回，省 token）→
用户问"还记得X吗"（查记忆意图）→ 路由器召回 X → 注入 → 回答。

### 验收测试（两层）
- ① 保存层：压 5-6 次后 X 在记忆里（durable）；
- ② 注入层：问"还记得X吗"召回结果含 X（routing 生效）。

## §4 沉淀机制（现状与重构）

- **事实（owner）**：现有沉淀按"同模式 ≥3 次"触发，**从未成功过一次**——count-based 在实践中不成立（用户很少短期机械重复同一模式）；
- **重构方向（待议）**：触发机制候选——用户显式（"保存为技能"，最稳）/ 跨会话复用（现实）/ 结果驱动（两次成功且被采纳，最接近"值得"）——或三者组合（显式最高优先 + 复用/结果后台检测）；
- **成本约束（owner 事实二）**：沉淀后 token 会涨——解法 = 休眠池 + 激活封顶 + 池上限 + 生命周期（§2.3），**能沉淀也能遗忘、能封顶**。
